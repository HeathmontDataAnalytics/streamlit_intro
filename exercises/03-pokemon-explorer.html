So far your apps have shown the same thing every time. Now you'll add widgets: checkboxes, drop-down menus and sliders that let the person using the app choose what to see.

You'll build a Pokémon explorer. The data, data/pokemon.csv, has one row for each Pokémon (including Mega and other special forms), with its types, its battle stats and its generation. It comes from Pokemon Stats by Ulrik Thyge Pedersen on Kaggle (licence: CC BY 4.0), with a few errors corrected.

In this exercise you will:

  • add a checkbox, a selectbox, a slider and a multiselect
  • use what the user picks to filter the data
  • let the user choose what a chart shows
  • lay out the app with a sidebar and columns

The big idea: every time someone changes a widget, Streamlit runs your whole script again from the top. This time, the widget gives back the new value. So you write a widget like a normal variable: chosen_type = st.selectbox(...).

The table is long, so let's hide it unless the user asks for it. st.checkbox("label") draws a checkbox and gives back True when it's ticked and False when it isn't.

Each Pokémon's total is the sum of its six battle stats. A slider lets the user pick a number by dragging. You give it a label, the smallest value, the largest value and the starting value:

A multiselect lets the user pick several options. It gives back a list. default= sets which options start selected.

Widgets can control charts too. Let the user choose which two stats to compare in a scatter plot. The selectbox gives back a column name, which you pass straight to Plotly as x or y.

An f-string puts variables into text: f"{y_stat} vs {x_stat}" could become "defense vs attack".

Real apps usually keep their controls in a sidebar and put headline numbers side by side in columns.

  • Everything indented under with st.sidebar: goes in the sidebar.
  • col1, col2, col3 = st.columns(3) makes three columns. Then col1.metric(...) puts a metric in the first one.

Also, if the filters match nothing, a chart of nothing is confusing. st.warning("...") shows a message, and st.stop() stops the script there, so nothing below it runs.
